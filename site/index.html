HOW IT WORKS

업무 등록부터 공개까지

이 페이지는 읽기 전용입니다. 내용 변경은 GitHub에서 로그인한 뒤 진행합니다.

1. 업무 등록

상단 ‘업무 등록’ 버튼으로 Issue 양식을 열고 단계, 상태, 시작일, 종료일, 공개 요약을 입력하세요. 날짜를 모르면 비워두면 됩니다.

2. 공개 현황판에 반영

관리자가 Issue에 dashboard 라벨을 추가하면 배포 워크플로가 데이터를 다시 생성합니다. 라벨은 현황판 표시 여부만 제어하며, Issue 자체를 비공개로 만들지는 않습니다.

3. 담당자·상태·진행률 변경

담당자는 Issue의 Assignees, 상태와 일정은 본문의 양식 항목에서 수정합니다. 진행률을 비우면 체크리스트 완료 비율을 사용합니다. 완료된 업무는 Issue를 ‘Completed’로 닫으세요. ‘Not planned’로 닫힌 업무는 취소로 처리합니다.

GitHub Projects 사용 시

동일 Issue를 Projects에 추가해 관리할 수 있습니다. 이 현황판은 Issue 본문·상태·담당자를 읽습니다. Projects의 독립적인 날짜·상태 필드와는 자동 동기화하지 않습니다.

갱신 시점

Issue 변경 이후 Actions 배포가 성공하면 새 데이터가 공개됩니다. ‘새로고침’은 배포된 최신 페이지를 다시 불러옵니다. 이 화면에서 배포를 직접 실행하지는 않습니다.

공개 저장소에는 비공개 연구자료를 넣지 마세요. 공개 라벨을 제거해도 기존 Issue·커밋·캐시는 사라지지 않습니다.
